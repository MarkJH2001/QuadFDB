A benchmark built around real flight

Feedback control can keep a quadrotor close to hover even when one motor loses actuation. If the fault lasts only a few hundred milliseconds, a diagnostic method must recognize a subtle response and identify the motor before the event ends.

QuadFDB brings together a dataset of 1,680 real flights, a fixed evaluation protocol, and baseline results. The study also introduces Residual-Augmented Gradient Boosting (RAGB), which combines healthy motion prediction errors, local motor class probabilities, and observed flight histories.

Real flight dataset

Motor faults under closed-loop control

Three Crazyflie 2.1+ quadrotors perform the same hover task with the standard PID controller. An onboard injector scales one motor’s PWM command after power distribution, while the feedback loop remains active. The records preserve the commanded actuation, resulting motion, and event timing.

156 fault conditions × 10 repetitions give 1,560 fault flights, complemented by 120 healthy controls. Four motor identities, three temporal profiles, and thirteen tested multipliers cover mild through severe faults.

Event evaluation

Diagnosis within the fault interval

A brief fault requires an alarm before the event ends and correct motor attribution at the first alarm. QuadFDB evaluates both outcomes using the recorded fault interval, alongside false alarms during healthy flight and the time needed to confirm a diagnosis.

  1. 01Observe16 samples over 300 ms
    Position, rates, motor commands
  2. 02CalibrateHealthy calibration scores
    99th-percentile threshold
  3. 03ConfirmTwo adjacent valid endpoints
    20 ms apart, before event end
  4. 04IsolateCorrect motor at the first alarm
    All fault flights retained

Six repetitions per condition are used for fitting, two for calibration, and two for testing. Every window from a flight stays in the same partition. Mild faults form one task; moderate and severe faults share a second fitted model and threshold.

Diagnostic method

Residual-Augmented Gradient Boosting

RAGB uses the relationship between motor commands and motion to describe a fault response. A predictor trained on healthy flights estimates motion from the preceding observations and commands. The signed prediction errors measure departures from that learned response, while a local random forest supplies probabilities for healthy operation and the four motor faults.

The classifier retains the observed history alongside these derived features: 160 normalized history values, 36 residual values, and five class probabilities form a 201-dimensional input to histogram gradient boosting. The resulting probabilities supply a fault score and candidate motor for the common alarm rule.

Whole-flight cross-fitting generates the predictor and RF outputs used to train the final classifier. For calibration and testing, the predictor is refitted on all healthy training windows and RF on all labeled training windows, while the final boosted classifier stays fixed.

Benchmark results

Detection, motor isolation, and timeliness

Nine tree, kernel, and neural references are evaluated alongside RAGB using the same flight partitions, available observations, and alarm rule. The strongest method depends on the fault regime and the diagnostic objective.

For mild faults, RAGB reaches 84.3% mean joint isolation, compared with 77.8% for RF. This gain accompanies more healthy alarms: 3.31 versus 2.17 per minute. Moderate and severe responses are easier to identify, bringing differences in false alarms and event coverage into focus.

Residuals help both classifiers on mild faults.

Adding residuals raises mild-fault joint isolation from 62.5% to 77.8% for HGB and from 53.2% to 65.7% for the control MLP. RF posteriors have a larger effect under boosting than under the neural classifier.

The preferred inputs vary with fault severity. For severe faults, HGB with residuals reaches 99.5% joint isolation, compared with 98.8% for the full inputs. For moderate faults, HGB with class posteriors matches RAGB’s isolation with fewer healthy alarms.

Conditional delay uses each method’s detected events, while paired timing compares detections shared by both methods. RAGB has a shorter conditional delay than RF; on shared mild-fault detections, the median paired timing difference is zero in each seed.
